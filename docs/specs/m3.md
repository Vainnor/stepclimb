# M3 Activities

- **Milestone:** M3, weeks 8 to 11

The `stepclimb-activities` engine: the `Activity` trait, seeded problem generation with
self-validation before serving, server-side step checks within 100 ms at p95, sessions, the step
log, active time from 15 s heartbeats, mastery rules and sprint mode. The built-in types for
every organization: drill games (matching, fill-in-the-blank, ordering), daily review with FSRS
spaced repetition, and the rule-checked form. Organization data sets (CSV or YAML, validated and
versioned) and the NASR and CIFP loader run each AIRAC cycle. In the optional ATC pack
(`stepclimb-activities-atc`, behind a cargo feature, enabled per organization): the flight plan
editor and runway heading activities, each with a known-case library that runs in CI and blocks
publishing a failing data set. The trainer report, session replay, the "This looks wrong" flag
and re-checking recorded sessions after a rule fix. The UI work is the Activities row
(ActivityShell, StepFeedback, the drill games, FlightPlanEditor, HeadingPicker, SprintHeader,
ReviewQueue, RuleForm, FlagProblem) and the M3 part of Reporting.

Plan: `docs/plan/technical.md` -> Interactive activities (Requirements, Activity types, Sprint
mode, Feedback settings, Data and correctness, What trainers see), Data model (activity tables),
API surface, Testing (Activities), Milestones; `docs/plan/ui.md` -> Component inventory
(Activities, Reporting), Signature components (ActivityShell and FlightPlanEditor).

Full spec: written before M3 starts.
