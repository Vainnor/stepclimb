# M2 Assessment

- **Milestone:** M2, weeks 5 to 8

`stepclimb-assess` with all ten question types (single choice, multiple response, true or false,
matching, ordering, short answer, numeric, cloze, hotspot, essay), graded only on the server and
also built for wasm32 for authoring previews and ungraded practice; question banks owned by an
account or course and shared down the tree, with tagged, versioned questions; the quiz builder
with fixed questions and pools; the attempt engine (draw, pin versions, seed, server deadline,
idempotent autosave, submit) and the deadline auto-submit job; the grading queue for essays and
unmatched answers; feedback settings during and after the attempt, with release timing and
presets, enforced by the API; accommodations; per-question statistics (facility,
discrimination, distractor rates, score distribution) with CSV export; CSV question import. The
UI work is the Assessment row (QuizShell, QuestionNavigator, Timer, SaveState, the renderers,
GradingPane, RubricGrid), the M2 part of Authoring (QuestionEditor, PoolBuilder, VersionDiff) and
of Reporting. Grading and feedback visibility get the maintainer's line-by-line review.

Plan: `docs/plan/technical.md` -> Assessments, Interactive activities (Feedback settings),
Progress and grades (Gradebook), Data model (assessment tables), API surface, Testing
(`stepclimb-assess`), Milestones; `docs/plan/ui.md` -> Component inventory (Assessment,
Authoring, Reporting), Signature components (QuizShell), Key layouts (Quiz, Grading queue).

Full spec: written before M2 starts.
