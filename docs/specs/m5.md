# M5 Apps, scenarios and ATC games

- **Milestone:** M5, weeks 14 to 21

The branching scenario activity and its visual graph editor, for every organization; in the ATC
pack, the ATC scenario (traffic picture and phraseology checked by a grammar), the ERAM/CRC
command drill, the clearance builder, the readback catcher, and METAR to runway configuration.
The Tauri 2 app for macOS, Windows, Linux and iOS around the same `web/` build: server discovery
through `/.well-known/stepclimb` and each server's `theme.css`, several linked servers, PKCE
sign-in in the system browser returning through a deep link against Stepclimb's own OAuth 2.1
server, refresh tokens in the OS keychain, offline course downloads, native notifications and
APNs, desktop auto-update, signed desktop builds from GitHub Releases, TestFlight and then the
App Store under the maintainer's Apple developer account. The UI work is the App shell row
(ServerPicker, ServerSwitcher, DownloadsManager, UpdatePrompt, NotificationSettings) and the M5
activities (CommandLine, ScenarioPlayer, ScenarioGraphEditor, TrafficPicture).

The 1.0 row (weeks 21 to 24) follows M5 and comes before M6: pilot fixes, the Helm chart, the k6
performance budgets, the security review and the API freeze.

Plan: `docs/plan/technical.md` -> Interactive activities (Activity types: M5 and 1.0 rows), Web
app and native apps (Tauri app), Identity and access (Sessions and tokens), Hosting and
operations (Kubernetes, Performance budgets), Testing (Apps, Load), Milestones (M5, 1.0);
`docs/plan/ui.md` -> Component inventory (App shell, Activities); ADR 0011.

Full spec: written before M5 starts.
