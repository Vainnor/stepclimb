# Architecture Rules (not loaded at startup; read in full before writing Rust, a migration or adding a dependency)

The crate map and dependency direction are in `AGENTS.md` -> Workspace layout. This file is how
to keep them true.

---

## Layering (`bin/check-layering.sh`, `just layering`)

- `stepclimb-assess` is pure and also builds for wasm32: no other workspace crate and no I/O,
  runtime or HTTP crate (`sqlx`, `tokio`, `axum`, `hyper`, `tower`, `reqwest`, `object_store`).
- `stepclimb-connectors` depends on no other workspace crate. Connectors use only the public API,
  as any outside system would, whether they run in the binary as jobs or as separate services.
- **Nothing VATSIM- or ATC-specific in the core.** Only `stepclimb-server` may depend on
  `stepclimb-activities-atc` or `stepclimb-connectors`, behind cargo features, enabled per
  organization. A vZDC rule, roster or term belongs in configuration or a data set.
- Nothing depends on `stepclimb-server`; it is the top of the graph.
- A new crate gets a rule in the script in the same change; the script fails on a crate without one.

## Server authority

- The server decides every outcome that counts: grades, completion, unlocks, deadlines, feedback
  visibility, activity checks. The client displays; it never decides. `assessment-integrity.md`
  has the rules for grading code.
- The deadline lives on the server; the client's countdown is display only.

## Tenancy

- **Every query is org-scoped.** Every row carries `org_id` (the `organizations` table is the
  scope itself), and every repository function takes an `OrgScope` and filters by it. A query
  that cannot take one names why in a comment. `security-and-tenancy.md` has the rest.

## Public API only

- Every client (the web app, the Tauri app, connectors, scripts) uses the public, versioned API
  under `/api/v1`, documented in the OpenAPI document. There are no private endpoints.
- Handlers carry `#[utoipa::path]`; `just openapi` regenerates `openapi/stepclimb.json` and the
  TypeScript client, and `just openapi-diff` fails when they are stale. Errors are
  `application/problem+json` with a stable `code`.
- A breaking change to a published endpoint is a new API version; the old one stays at least 12
  months.

## Database

- PostgreSQL 16+ through sqlx with compile-checked queries (`query!`, `query_as!`); `.sqlx/` is
  committed and `just sqlx-check` fails when it is stale. Run `just sqlx-prepare` after changing a
  query.
- Migrations are forward-only (expand, then contract in a later release), embedded and run at
  startup. An applied migration is never edited.
- Keys are UUID v7 generated by the server; `created_at` and `updated_at` everywhere.

## Crate boundaries

- A new crate needs an ADR. Prefer a module in an existing crate until the boundary is proven.
- Data formats (course archive, data sets, export files) are versioned from their first release.

## Dependencies

- **Pin every version exactly**: Rust in the root `[workspace.dependencies]` (`=x.y.z`), members
  use `.workspace = true`; npm packages exact in `package.json` (`saveExact`).
- **Nothing published less than 14 days ago.** pnpm enforces it (`minimumReleaseAge`); check a
  crate's release date on crates.io before pinning it.
- A framework pin or major upgrade (axum, sqlx, utoipa, tokio, React, Vite, Tauri, Tailwind)
  gets an ADR and its own commit. Lockfile-only changes go in their own commit.
- Run `dependency-researcher` before adding a large dependency. Every addition passes `just deny`
  (licenses compatible with AGPL-3.0-or-later; no GPL-2.0-only) and `just layering`.
- No git dependencies (`deny.toml` refuses unknown git sources).

## Errors

Library crates return typed errors (`thiserror`); binaries may use a report type at the top
level. No `unwrap` or `expect` outside tests unless the invariant is stated in a comment beside it.
